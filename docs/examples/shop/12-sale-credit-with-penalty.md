# 12-sale-credit-with-penalty.md
## سناریو
فروش نسیه با جریمه دیرکرد (فرض بر ثبت اولیه فروش، جریمه جداگانه).

> **توضیح مهم:** جریمه دیرکرد در این فایل صرفاً یک سناریوی دامنه‌ای است. پکیج هسته حسابداری درباره وجود یا عدم وجود جریمه، نحوه محاسبه آن، وضعیت مالیاتی آن یا زمان شناسایی‌اش تصمیم‌گیری نمی‌کند؛ همه این موارد باید در قرارداد تجاری، منطق برنامه مصرف‌کننده و چارت حساب‌های همان سامانه تعیین شوند.

---
## فرضیات
* تعداد محصولات: 3 عدد
* قیمت هر محصول: 1,000,000 تومان
* تخفیف محصول: ندارد
* تخفیف فاکتور: ندارد
* هزینه باربری: 100,000 تومان (در این مثال مشمول مالیات فرض شده است)
* نرخ مالیات بر ارزش افزوده: 10٪
* جریمه دیرکرد: 50,000 تومان (در این مثال به‌عنوان درآمد جداگانه فرض شده است)
* روش پرداخت: نسیه

## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا
```
3 × 1,000,000 = 3,000,000
```
### 2. تخفیف
```
ندارد → مبلغ تغییری نمی‌کند
```
### 3. مالیات کالا
```
3,000,000 × 10٪ = 300,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. جریمه
```
50,000 (در این مثال بدون مالیات فرض شده است)
```
### 6. مبلغ نهایی
```
3,410,000 + 50,000 = 3,460,000
```

## سند حسابداری

## شرط‌های فعال در این سناریو
* فروش نسیه
* فروش مشمول مالیات در فرض این مثال
* وجود باربری
* جریمه دیرکرد

## شرط‌های غیرفعال
* تخفیف محصول
* تخفیف فاکتور
* پرداخت نقدی
* پیش‌دریافت
* برگشت از فروش

---
## نکات مرجع
* ثبت جریمه به‌عنوان درآمد جداگانه فقط یکی از مدل‌های ممکن است و هسته پکیج چنین رفتاری را تحمیل نمی‌کند.
* مالیاتی بودن یا نبودن جریمه، و حتی امکان مطالبه آن، باید مطابق قوانین، قرارداد و منطق برنامه مصرف‌کننده تعیین شود.
