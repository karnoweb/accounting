# 15-sale-mixed-cash-credit.md
## سناریو
فروش ترکیبی نقدی و نسیه.

> **توضیح مهم:** این مثال فقط یک ترکیب مفهومی از بخش نقدی و بخش نسیه را نشان می‌دهد. پکیج هسته حسابداری به‌تنهایی فاکتور فروش، مدیریت مشتری، تخصیص مبلغ بین روش‌های پرداخت یا قواعد وصول را پیاده‌سازی نمی‌کند؛ این تصمیم‌ها باید در اپلیکیشن مصرف‌کننده گرفته شوند و سپس به ثبت‌های حسابداری متناظر تبدیل شوند.

---
## فرضیات
* تعداد محصولات: 3 عدد
* قیمت هر محصول: 1,000,000 تومان
* تخفیف محصول: ندارد
* تخفیف فاکتور: ندارد
* هزینه باربری: 100,000 تومان (در این مثال مشمول مالیات فرض شده است)
* نرخ مالیات بر ارزش افزوده: 10٪
* پرداخت: 1,705,000 نقدی، 1,705,000 نسیه

## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا
```
3 × 1,000,000 = 3,000,000
```
### 2. تخفیف
```
ندارد → مبلغ تغییری نمی‌کند
```
### 3. مالیات کالا
```
3,000,000 × 10٪ = 300,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. مبلغ نهایی
```
3,410,000
```
### 6. پرداخت ترکیبی
```
1,705,000 نقدی، 1,705,000 نسیه
```

## سند حسابداری
در این الگو، بخشی از مبلغ در لحظه فروش وصول می‌شود و بخش دیگر به‌عنوان مانده قابل وصول باقی می‌ماند. اینکه این تقسیم در سیستم فروش، پرداخت یا قرارداد چگونه نگه‌داری شود، جزو منطق برنامه مصرف‌کننده است نه رفتار از پیش‌تعیین‌شده هسته.

## نکات مرجع
* تقسیم مبلغ بین نقد و نسیه در این سند یک انتخاب نمونه است و هسته پکیج نسبت‌ها، روش تخصیص یا تعداد ابزارهای پرداخت را enforce نمی‌کند.
* از دید حسابداری، ساختار کلی سند می‌تواند مشابه فروش عادی بماند؛ تفاوت اصلی در نگاشت بخشی از مبلغ به حساب وصول و بخشی به حساب دریافتنی است، آن هم با توجه به چارت حساب‌ها و منطق برنامه مصرف‌کننده.
