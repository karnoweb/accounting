# 31-shipping-expense.md
> این فایل مثال دامنه است. هسته پکیج ماژول باربری ندارد و تعیین این‌که هزینه ارسال از مشتری دریافت شود یا به‌عنوان هزینه داخلی ثبت شود، تصمیم اپلیکیشن مصرف‌کننده و نگاشت حساب‌های آن است.
## سناریو
باربری به عنوان هزینه داخلی فروشگاه (پرداخت به شرکت باربری)، در حالی که مبلغی بابت ارسال از مشتری دریافت نشده است.
---
## فرضیات
* فروش کالا: 3,000,000 تومان
* باربری پرداختی: 150,000 تومان (هزینه داخلی فروشگاه)
* نرخ مالیات: 10٪ روی کالا
* روش پرداخت: نقدی برای فروش
---

## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا
```
3 × 1,000,000 = 3,000,000
```
### 2. مالیات کالا
```
3,000,000 × 10٪ = 300,000
```
### 3. باربری هزینه
```
150,000 (در اپ فروشگاه به‌عنوان هزینه جداگانه ثبت می‌شود)
```
### 4. مبلغ نهایی دریافتی
```
3,000,000 + 300,000 = 3,300,000
```

## شرط‌های فعال در این سناریو
* فروش نقدی
* فروش مشمول مالیات در سیاست اپ
* باربری به عنوان هزینه داخلی
## شرط‌های غیرفعال
* دریافت باربری از مشتری
* تخفیف
* فروش نسیه

## نکات مرجع
* این مثال فرض می‌کند هزینه باربری از مشتری اخذ نشده و فقط در دفاتر داخلی فروشگاه به‌عنوان هزینه ثبت شده است.
* هسته پکیج تصمیم نمی‌گیرد باربری «درآمد» است یا «هزینه»؛ فقط ردیف‌های سندی را که اپ شما ساخته ثبت می‌کند.
* کد حساب‌های هزینه و نقد/بانک باید با chart of accounts واقعی پروژه شما هماهنگ شوند.
