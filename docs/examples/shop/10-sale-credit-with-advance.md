# 10-sale-credit-with-advance.md
## سناریو
فروش نسیه با پیش‌دریافت (پرداخت بخشی اولیه).

> **توضیح مهم:** این مثال یک سناریوی مفهومی در سطح کسب‌وکار است تا منطق ثبت‌های حسابداری را نشان دهد. پکیج هسته حسابداری به‌تنهایی ماژول فروش، مشتری، دریافتنی، باربری یا مالیات را enforce نمی‌کند؛ انتخاب سرفصل‌ها، زمان شناسایی پیش‌دریافت و نحوه نگهداری مانده باقیمانده به چارت حساب‌ها و منطق برنامه مصرف‌کننده بستگی دارد.

---
## فرضیات
* تعداد محصولات: 3 عدد
* قیمت هر محصول: 1,000,000 تومان
* تخفیف محصول: ندارد
* تخفیف فاکتور: ندارد
* هزینه باربری: 100,000 تومان (در این مثال مشمول مالیات فرض شده است)
* نرخ مالیات بر ارزش افزوده: 10٪
* پیش‌دریافت: 1,000,000 تومان (در این مثال نقدی فرض شده است)
* روش پرداخت: نسیه برای باقیمانده

## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا
```
3 × 1,000,000 = 3,000,000
```
### 2. تخفیف
```
ندارد → مبلغ تغییری نمی‌کند
```
### 3. مالیات کالا
```
3,000,000 × 10٪ = 300,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. مبلغ نهایی
```
3,410,000
```
### 6. پیش‌دریافت
```
1,000,000 (در این مثال نقدی دریافت شده)
باقیمانده: 3,410,000 - 1,000,000 = 2,410,000
```

## شرط‌های فعال در این سناریو
* فروش نسیه
* فروش مشمول مالیات در فرض این مثال
* وجود باربری
* پیش‌دریافت

## شرط‌های غیرفعال
* تخفیف محصول
* تخفیف فاکتور
* پرداخت کامل نقدی
* برگشت از فروش

---
## نکات مرجع
* در این سناریو پیش‌دریافت به صندوق رفته و باقیمانده به دریافتنی منتقل شده است، اما پکیج هسته چنین نگاشتی را به‌صورت ذاتی تحمیل نمی‌کند.
* شناسایی کامل درآمد در زمان فروش یک سیاست حسابداری نمونه است و در برنامه مصرف‌کننده باید با چرخه اسناد و قواعد کسب‌وکار همان سیستم منطبق شود.
