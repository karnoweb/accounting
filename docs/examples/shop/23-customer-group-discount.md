# 23-customer-group-discount.md

> این فایل یک **مثال مفهومی فروشگاهی** است، نه قرارداد رفتاری هسته پکیج. تشخیص گروه مشتری، احراز شرایط عضویت، و تعیین درصد تخفیف در اپلیکیشن مصرف‌کننده انجام می‌شود؛ هسته فقط سندهای متعادل را ذخیره می‌کند و بر مبنای داده‌های دفتر کل گزارش می‌دهد.

## سناریو
یک مثال از فروشی که در لایه اپلیکیشن، به دلیل تعلق مشتری به یک گروه خاص، تخفیف 12٪ برای آن محاسبه شده است.
---
## فرضیات
* تعداد محصولات: 3 عدد
* قیمت هر محصول: 1,000,000 تومان
* تخفیف گروه: 12٪ برای یک گروه مشتری، به عنوان قاعده دامنه اپلیکیشن
* هزینه باربری: 100,000 تومان (مشمول مالیات)
* نرخ مالیات بر ارزش افزوده: 10٪
* روش پرداخت: نقدی
---

---
## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا قبل از تخفیف
```
3 × 1,000,000 = 3,000,000
```
### 2. تخفیف گروه
```
هر محصول: 1,000,000 × 12٪ = 120,000
جمع تخفیف: 3 × 120,000 = 360,000
مبلغ خالص کالا: 3,000,000 - 360,000 = 2,640,000
```
### 3. مالیات کالا
```
2,640,000 × 10٪ = 264,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. مبلغ نهایی دریافتی
```
2,640,000 + 264,000 + 100,000 + 10,000 = 3,014,000
```

## نکات مرجع
* هسته پکیج هیچ مفهوم داخلی برای «گروه مشتری» ندارد و صرفا اثر مالی خروجیِ این تصمیم دامنه را ثبت می‌کند.
* از دید حسابداری، این سناریو تفاوت ماهوی با سایر حالت‌های کاهش مبلغ فروش ندارد؛ تفاوت در علت تجاری آن است که در اپلیکیشن نگهداری می‌شود.
* اگر پروژه شما منطق متفاوتی برای توزیع تخفیف بین اقلام یا محاسبه مالیات داشته باشد، باید همان خروجی دامنه را به سند متعادل تبدیل کند.
