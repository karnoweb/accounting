# 22-volume-discount.md

> این فایل یک **مثال مفهومی فروشگاهی** است، نه قرارداد رفتاری هسته پکیج. قواعدی مثل «بیش از 4 عدد»، درصد تخفیف، و تشخیص آستانه حجمی در اپلیکیشن مصرف‌کننده تعیین می‌شوند؛ هسته فقط سند متعادل و گزارش‌های مبتنی بر دفتر کل را نگه می‌دارد.

## سناریو
یک مثال از فروشی که در لایه اپلیکیشن، به دلیل عبور از آستانه تعداد، تخفیف حجمی برای آن محاسبه شده است.
---
## فرضیات
* تعداد محصولات: 5 عدد (برای فعال شدن تخفیف حجمی)
* قیمت هر محصول: 1,000,000 تومان
* تخفیف حجمی: 8٪ برای بیش از 4 عدد، به عنوان یک قاعده دامنه در اپلیکیشن
* هزینه باربری: 100,000 تومان (مشمول مالیات)
* نرخ مالیات بر ارزش افزوده: 10٪
* روش پرداخت: نقدی
---
## جدول فاکتور فروش
| ردیف | عنوان / محصول | قیمت پایه | تعداد | تخفیف % | مبلغ تخفیف | مبلغ خالص | مالیات % | مبلغ مالیات | مبلغ کل |
| ---: | -------------------------- | --------: | ----: | ------: | ---------: | ------------: | -------: | ----------: | ------------: |
| 1 | محصول A | 1,000,000 | 5 | 8٪ | 400,000 | 4,600,000 | 10٪ | 460,000 | 5,060,000 |
| | **جمع کالا** | | | | **400,000** | **4,600,000** | | **460,000** | **5,060,000** |
| 2 | هزینه باربری | – | – | – | – | 100,000 | 10٪ | 10,000 | 110,000 |
| | **مبلغ نهایی قابل پرداخت** | | | | | | | | **5,170,000** |
---
## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا قبل از تخفیف
```
5 × 1,000,000 = 5,000,000
```
### 2. تخفیف حجمی
```
5,000,000 × 8٪ = 400,000
مبلغ خالص کالا: 5,000,000 - 400,000 = 4,600,000
```
### 3. مالیات کالا
```
4,600,000 × 10٪ = 460,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. مبلغ نهایی دریافتی
```
4,600,000 + 460,000 + 100,000 + 10,000 = 5,170,000
```

* فروش نقدی
* فروش مشمول مالیات
* وجود باربری
* وجود سیاست تخفیف حجمی در لایه اپلیکیشن
## شرط‌های غیرفعال

## نکات مرجع
* هسته پکیج نه «آستانه حجمی» را می‌شناسد و نه خودِ قاعده تخفیف را اجرا می‌کند؛ فقط ارقام نهایی سند را ثبت می‌کند.
* این مثال نشان می‌دهد وقتی اپلیکیشن پس از ارزیابی تعداد، مبلغ فروش را کاهش می‌دهد، ثبت حسابداری همچنان همان الگوی سند متعادل را دنبال می‌کند.
* فرض بهای تمام‌شده این سناریو نیز صرفا آموزشی است و باید با مدل موجودی و حساب‌های واقعی پروژه شما جایگزین شود.
