# 16-sale-wallet.md
## سناریو
فروش با پرداخت از کیف پول مشتری.

> **توضیح مهم:** «کیف پول» در این فایل فقط یک مفهوم دامنه‌ای برای نگه‌داری اعتبار یا سپرده مشتری است. پکیج هسته حسابداری خودش زیرسیستم کیف پول، شارژ، برداشت، بلوکه‌کردن اعتبار یا قوانین مصرف موجودی را ارائه نمی‌دهد؛ برنامه مصرف‌کننده باید این رفتارها را تعریف کند و سپس اثر مالی آن‌ها را به ثبت‌های حسابداری متصل کند.

---
## فرضیات
* تعداد محصولات: 3 عدد
* قیمت هر محصول: 1,000,000 تومان
* تخفیف محصول: ندارد
* تخفیف فاکتور: ندارد
* هزینه باربری: 100,000 تومان (در این مثال مشمول مالیات فرض شده است)
* نرخ مالیات بر ارزش افزوده: 10٪
* روش پرداخت: از کیف پول (فرض بر حساب ودیعه مشتری)

## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا
```
3 × 1,000,000 = 3,000,000
```
### 2. تخفیف
```
ندارد → مبلغ تغییری نمی‌کند
```
### 3. مالیات کالا
```
3,000,000 × 10٪ = 300,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. مبلغ نهایی
```
3,410,000 (در این مثال از مانده کیف پول کسر می‌شود)
```

* پرداخت از کیف پول
* فروش مشمول مالیات در فرض این مثال
* وجود باربری

## نکات مرجع
* نمایش کیف پول به‌عنوان بدهی/ودیعه فقط یکی از مدل‌های ممکن است و هسته پکیج چنین ساختاری را به‌طور پیش‌فرض ایجاد یا enforce نمی‌کند.
* از نظر ثبت مالی، این سناریو می‌تواند شبیه فروش نقدی باشد با این تفاوت که طرف بدهکار ممکن است به‌جای صندوق/بانک، حساب اعتبار یا سپرده مشتری باشد؛ انتخاب دقیق آن با برنامه مصرف‌کننده است.
