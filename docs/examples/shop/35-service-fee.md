# 35-service-fee.md

> این فایل مثال دامنه است. هسته پکیج هیچ policy داخلی برای «هزینه خدمات» ندارد؛ فقط فرض می‌کنیم اپلیکیشن مصرف‌کننده این مبلغ را در فاکتور محاسبه کرده و به حساب‌های متناظر خود نگاشت می‌کند.

## سناریو

افزودن مبلغ خدمات جانبی به فاکتور فروش، با این فرض که فروشگاه این مبلغ را جدا از فروش کالا از مشتری دریافت می‌کند.

---

## فرضیات

* مبلغ خدمات: 80,000 تومان (در این مثال مشمول 10٪ بر اساس سیاست اپ)
* بقیه مشابه 01 (۳ محصول، باربری 100,000، نرخ مالیات 10٪)

---

| ---: | -------------------------- | --------: | ----: | ------: | ---------: | ------------: | -------: | ----------: | ------------: |

## منطق محاسبات (عدد به عدد)

### 1. جمع فروش کالا

```
3 × 1,000,000 = 3,000,000
```

### 2. مالیات کالا

```
3,000,000 × 10٪ = 300,000
```

### 3. باربری

```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```

### 4. هزینه خدمات

```
80,000 + (80,000 × 10٪) = 80,000 + 8,000 = 88,000
```

### 5. مبلغ نهایی دریافتی

```
3,000,000 (کالا)
+ 300,000 (مالیات کالا)
+ 100,000 (باربری)
+ 10,000 (مالیات باربری)
+ 80,000 (خدمات)
+ 8,000 (مالیات خدمات)
= 3,498,000
```

## شرط‌های فعال در این سناریو

* فروش نقدی
* دریافت مبلغ خدمات جانبی
* فروش مشمول مالیات در این مثال
* وجود باربری

## شرط‌های غیرفعال

* تخفیف
* فروش نسیه

---

## نکات مرجع

* این مثال فقط نشان می‌دهد یک اپ مصرف‌کننده می‌تواند مبلغ خدمات را به‌صورت ردیف جداگانه در فاکتور بیاورد.
* هسته پکیج نمی‌داند «هزینه خدمات» چیست و برای آن rule محاسباتی یا حقوقی ندارد.
* مالیات این ردیف نیز در این مستند یک فرض دامنه‌ای است؛ اگر خدمات شما معاف، غیرمشمول یا با نرخ دیگری باشند، همان سیاست باید در اپ اعمال شود.
