# 11-sale-credit-multi-due.md
## سناریو
فروش نسیه با چندین سررسید پرداخت.

> **توضیح مهم:** این فایل یک مثال مفهومی برای مدل‌سازی سناریوی فروش اقساطی یا چندسررسیدی است. پکیج هسته حسابداری به‌تنهایی موتور اقساط، سررسید، پیگیری وصول یا قرارداد مشتری را فراهم نمی‌کند؛ این موارد باید در برنامه مصرف‌کننده تعریف شوند و سپس به ثبت‌های حسابداری متناظر نگاشت شوند.

---
## فرضیات
* تعداد محصولات: 3 عدد
* قیمت هر محصول: 1,000,000 تومان
* تخفیف محصول: ندارد
* تخفیف فاکتور: ندارد
* هزینه باربری: 100,000 تومان (در این مثال مشمول مالیات فرض شده است)
* نرخ مالیات بر ارزش افزوده: 10٪
* روش پرداخت: نسیه با 2 سررسید (1,705,000 هر کدام)

## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا
```
3 × 1,000,000 = 3,000,000
```
### 2. تخفیف
```
ندارد → مبلغ تغییری نمی‌کند
```
### 3. مالیات کالا
```
3,000,000 × 10٪ = 300,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. مبلغ نهایی
```
3,410,000
```
### 6. تقسیم سررسید
```
3,410,000 / 2 = 1,705,000 هر سررسید
```

## سند حسابداری
در این مثال، سررسیدها فقط به‌عنوان منطق تجاری بیرون از هسته در نظر گرفته شده‌اند. بنابراین سند نمونه، مبلغ کل دریافتنی را نشان می‌دهد و ریز سررسیدها باید در لایه کاربردی یا زیرسیستم قرارداد/وصول مدیریت شوند.

## شرط‌های فعال در این سناریو
* فروش نسیه
* فروش مشمول مالیات در فرض این مثال
* وجود باربری
* چندین سررسید

## شرط‌های غیرفعال
* تخفیف محصول
* تخفیف فاکتور
* پرداخت نقدی
* پیش‌دریافت
* برگشت از فروش

---
## نکات مرجع
* ثبت کل دریافتنی در این مثال به این معنی نیست که پکیج هسته به‌طور پیش‌فرض سررسیدها را نگه‌داری یا پیگیری می‌کند؛ این رفتار باید در لایه دامنه یا برنامه مصرف‌کننده ساخته شود.
* چندسررسیدی بودن لزوماً ساختار سند حسابداری را عوض نمی‌کند، اما ممکن است در برخی پیاده‌سازی‌ها به تفکیک حساب، اسناد میانی یا ثبت‌های تکمیلی نیاز باشد.
