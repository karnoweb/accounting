# 01-sale-cash-no-discount.md

> این فایل یک **مثال مفهومی فروشگاهی** است، نه قرارداد رفتاری هسته پکیج. مفاهیمی مثل کالا، مالیات، باربری و بهای تمام‌شده باید در اپلیکیشن مصرف‌کننده مدل شوند.

> نکته Contract هسته پکیج:
> - هسته فقط «سند متعادل» را ثبت می‌کند (جمع ردیف‌ها باید بالانس شود).
> - ردیف سند فقط روی حساب‌های قابل‌ثبت (postable) مجاز است.
> - کد حساب‌هایی که اینجا می‌بینید، نمونه هستند و باید با Chart of Accounts واقعی پروژهٔ شما هم‌راستا شوند.

## سناریو

فروش نقدی کالا بدون هیچ‌گونه تخفیف (نه روی محصول و نه روی فاکتور)

---

## فرضیات

* تعداد محصولات: 3 عدد
* قیمت هر محصول: 1,000,000 تومان
* تخفیف محصول: ندارد
* تخفیف فاکتور: ندارد
* هزینه باربری: 100,000 تومان (مشمول مالیات)
* نرخ مالیات بر ارزش افزوده: 10٪
* روش پرداخت: نقدی

---

## منطق محاسبات (عدد به عدد)

### 1. جمع فروش کالا

```
3 × 1,000,000 = 3,000,000
```

### 2. تخفیف

```
ندارد → مبلغ تغییری نمی‌کند
```

### 3. مالیات کالا

```
3,000,000 × 10٪ = 300,000
```

### 4. باربری

```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```

### 5. مبلغ نهایی دریافتی

```
3,000,000 (کالا)
+ 300,000 (مالیات کالا)
+ 100,000 (باربری)
+ 10,000 (مالیات باربری)
= 3,410,000
```

> نکته: هسته پکیج فقط «بالانس دوبل» را enforce می‌کند. کد حساب‌هایی که در جدول می‌بینید باید با کدهای واقعی Chart of Accounts پروژه شما جایگزین شوند.

* تخفیف فاکتور

* برگشت از فروش

---

## نکات مرجع

* عدم وجود تخفیف فقط باعث افزایش مبلغ درآمد می‌شود
* ساختار سند نسبت به حالت تخفیف‌دار تغییری نمی‌کند
* نحوه ثبت مالیات در سند به ماهیت حساب‌های پروژه شما در `accounts` (و انتخاب حساب مناسب برای مالیات) وابسته است.

این سناریو فقط یک نمونهٔ آموزشی از شکل کلی ثبت دوبل است.
