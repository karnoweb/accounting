# 26-mixed-tax-items.md
> این فایل یک مثال دامنه‌محور است. هسته پکیج خودش تشخیص نمی‌دهد کدام قلم مشمول یا غیرمشمول است؛ اپلیکیشن مصرف‌کننده باید این برچسب‌ها و نگاشت حساب‌ها را تعیین کند.
## سناریو
فروش با آیتم‌های مشمول و غیرمشمول مالیات، با این فرض که لایه فروشگاه برای هر قلم نرخ مناسب را از قبل تعیین کرده است.
---
## فرضیات
* محصول A و B: 1,000,000 تومان هر کدام، در سیاست مالیاتی اپ مشمول 10٪
* محصول C: 1,000,000 تومان، در سیاست مالیاتی اپ غیرمشمول
* تخفیف: ندارد
* هزینه باربری: 100,000 تومان (مشمول 10٪)
* روش پرداخت: نقدی
---
## جدول فاکتور فروش
| ردیف | عنوان / محصول | قیمت پایه | تعداد | تخفیف % | مبلغ تخفیف | مبلغ خالص | مالیات % | مبلغ مالیات | مبلغ کل |
| ---: | -------------------------- | --------: | ----: | ------: | ---------: | ------------: | -------: | ----------: | ------------: |
| 1 | محصول A (مشمول) | 1,000,000 | 1 | – | – | 1,000,000 | 10٪ | 100,000 | 1,100,000 |
| 2 | محصول B (مشمول) | 1,000,000 | 1 | – | – | 1,000,000 | 10٪ | 100,000 | 1,100,000 |
| 3 | محصول C (غیرمشمول) | 1,000,000 | 1 | – | – | 1,000,000 | 0٪ | 0 | 1,000,000 |
| | **جمع کالا** | | | | | **3,000,000** | | **200,000** | **3,200,000** |
| 4 | هزینه باربری | – | – | – | – | 100,000 | 10٪ | 10,000 | 110,000 |
| | **مبلغ نهایی قابل پرداخت** | | | | | | | | **3,310,000** |
---
## منطق محاسبات (عدد به عدد)
### 1. جمع فروش کالا
```
3 × 1,000,000 = 3,000,000
```
### 2. تخفیف
```
ندارد
```
### 3. مالیات کالا
```
A و B: 2,000,000 × 10٪ = 200,000
C: 1,000,000 × 0٪ = 0
جمع مالیات کالا: 200,000
```
### 4. باربری
```
باربری = 100,000
مالیات باربری = 100,000 × 10٪ = 10,000
```
### 5. مبلغ نهایی
```
3,000,000 + 200,000 + 100,000 + 10,000 = 3,310,000
```

## شرط‌های فعال در این سناریو
* فروش نقدی
* ترکیب اقلام با نرخ‌های متفاوت در سیاست اپ
* وجود باربری
## شرط‌های غیرفعال
* تخفیف
* فروش نسیه
* پیش‌دریافت
* برگشت از فروش

## نکات مرجع
* در این مثال، محاسبه مالیات هر آیتم به‌صورت سطری نشان داده شده تا روشن باشد تفکیک مشمول/غیرمشمول در داده‌های ورودی اپ انجام شده است.
* هسته پکیج هیچ rule داخلی برای تشخیص این‌که «محصول C باید 0٪ باشد» ندارد و فقط سند نهایی متعادل را ثبت می‌کند.
* کد حساب‌های درآمد، باربری و مالیات نمونه هستند و باید با chart of accounts واقعی پروژه شما جایگزین شوند.
