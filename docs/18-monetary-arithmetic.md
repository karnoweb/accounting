# حسابداری مبلغ‌ها (Monetary Arithmetic)

این سند قرارداد هسته برای نمایش، محاسبه و مقایسهٔ مبلغ‌ها است.

## قانون مشارکت‌کنندگان

> Monetary accounting calculations must never use PHP floating-point arithmetic.

محاسبه، جمع، تفریق، نقیض، مقایسه، تست صفر، و تبدیل بدهکار/بستانکار باید از `Karnoweb\Accounting\Support\Amount` بگذرد.

ممنوع:

- `(float) $amount` برای محاسبه
- `floatval(...)` برای محاسبه
- `$debit + $credit` / `$amount * $sign` روی مقدارهای پولی
- `abs($balance) < 0.01` برای تعادل سند
- `round($amount, 2)` به‌جای `Amount::of($amount)`
- تبدیل ستون `DECIMAL` به float برای راحتی

## نمایش کانونیکال

`Amount` یک value object تغییرناپذیر است که مقدار را به‌صورت رشتهٔ اعشاری نگه می‌دارد و با **BCMath** حساب می‌کند.

```php
use Karnoweb\Accounting\Support\Amount;

$sum = Amount::of('0.10')->add('0.20');
$sum->equals('0.30');          // true
$sum->isZero();                // false
$sum->toStorage();             // "0.30" — برای persist / SQL
$sum->toFloat();               // فقط مرز API عمومی
```

این پکیج مدل **مبلغ** دارد، نه Money چندارزی. واحد پول در هسته مدل نشده است.

## مقیاس‌ها

| لایه | منبع | مقدار پیش‌فرض |
|------|------|----------------|
| ذخیره‌سازی | ستون‌های `decimal(15,2)` و `accounting.general.decimal_places` | ۲ |
| محاسبه | BCMath با مقیاس کاری بالاتر، سپس نرمال‌سازی به مقیاس ذخیره‌سازی | ≥ ۸ کاری / ۲ نهایی |
| نمایش / API سازگار | `Amount::toFloat()` فقط در مرز عمومی | همان مقیاس ذخیره‌سازی |

گرد کردن ورودی به مقیاس ذخیره‌سازی: **half away from zero** (همان قرارداد `round()` در PHP برای ورودی رشته‌ای دقیق).

ورودی `float` فقط در مرز API پذیرفته می‌شود و فوراً به اعشار نرمال می‌شود. برای مبلغ‌های بزرگ یا مقادیر حساس، رشته بدهید (`'0.10'`، `'999999999999.99'`).

## مقایسه و تعادل

تعادل سند:

```text
sum(amount × sign) == 0
```

با `Amount::isZero()` در مقیاس ذخیره‌سازی. تلورانس اپسیلون وجود ندارد.

`0.01` اختلاف است و سند را رد می‌کند. `0.00` متعادل است.

## بدهکار / بستانکار

| نوع ردیف | amount | sign | debit | credit |
|----------|--------|------|-------|--------|
| بدهکار | `100.00` | `1` | `100.00` | `0.00` |
| بستانکار | `100.00` | `-1` | `0.00` | `100.00` |

`DocumentItem` هنگام ذخیره `debit`/`credit` را از `amount` و `sign` با `Amount` می‌سازد. هیچ تبدیلی از float رد نمی‌شود.

## انتظارات API

متدها و DTOهای موجود که قبلاً `float` برمی‌گرداندند (`debit_total`، `BalanceService::getBalance()`، `LedgerLine::$debit`، …) همچنان `float` برمی‌گردانند تا مصرف‌کننده‌ها نشکنند.

این float فقط خروجی مرز است. مصرف‌کننده و مشارکت‌کننده نباید آن را دوباره جمع کنند.

ورودی‌های builder و سرویس‌ها `int|float|string` را می‌پذیرند. رشته ترجیح داده می‌شود.

```php
Accounting::document()
    ->debit($cash, '0.10')
    ->debit($cash, '0.20')
    ->credit($revenue, '0.30')
    ->post();
```

## Schema

ستون‌های پولی فعلی `decimal(15,2)` می‌مانند. این نسخه migration ندارد.

بزرگ‌ترین مقدار پشتیبانی‌شده توسط schema: `9999999999999.99` (۱۵ رقم، ۲ اعشار).

## واژه‌نامه

| اصطلاح | معنی |
|--------|------|
| Amount | مقدار اعشاری حسابداری بدون ارز |
| Storage scale | تعداد اعشار ذخیره‌شده و مقایسه‌شده |
| BCMath | حساب دقیق اعشاری PHP |
| toFloat() | تبدیل مرز API؛ برای محاسبهٔ دفتر استفاده نشود |
| Epsilon | تلورانس شناور مثل `abs(x) < 0.01` — در هسته ممنوع است |
