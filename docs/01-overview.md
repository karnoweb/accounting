# معرفی کلی پکیج حسابداری

## Overview

---

## هدف پکیج

این پکیج یک **هسته حسابداری مستقل و قابل استفاده مجدد** برای Laravel است که بدون وابستگی به منطق تجاری پروژه‌ها (فروشگاه، آموزشگاه، SaaS و...) طراحی شده است.

### چرا این پکیج ساخته شد؟

| مشکل | راه‌حل این پکیج |
|------|-----------------|
| هر پروژه حسابداری خودش را از صفر می‌سازد | یک هسته آماده و تست‌شده |
| منطق حسابداری با منطق تجاری قاطی می‌شود | جداسازی کامل Domain ها |
| تغییر در یک بخش، بخش‌های دیگر را خراب می‌کند | API ثابت و پایدار |
| گزارش‌گیری پیچیده و ناهماهنگ | گزارش‌های استاندارد آماده |
| عدم رعایت اصول حسابداری | اجبار به ثبت صحیح (بالانس) |

---

## فلسفه طراحی

### رویکرد Account-Centric

در این پکیج **هر چیزی که اثر مالی دارد، یک حساب (Account) است**.

| موجودیت در پروژه | معادل در حسابداری |
|------------------|-------------------|
| کاربر / مشتری | حساب بدهکار |
| تأمین‌کننده | حساب بستانکار |
| محصول | حساب موجودی کالا |
| بانک | حساب بانک |
| صندوق | حساب صندوق |
| درآمد فروش | حساب درآمد |
| هزینه حقوق | حساب هزینه |

### چرا این رویکرد؟

**مزیت ۱: یکنواختی کامل**

همه موجودیت‌ها فقط «حساب» هستند. نیازی به جداول مختلف برای انواع تراکنش‌ها نیست.

**مزیت ۲: سادگی Query**

به جای Join های پیچیده بین جداول مختلف، فقط با یک جدول accounts کار می‌کنید.

**مزیت ۳: عدم نیاز به Polymorphic**

در اسناد حسابداری نیازی به `accountable_type` و `accountable_id` نیست. هر آیتم مستقیماً به `account_id` وصل است.

**مزیت ۴: گزارش‌گیری ساده**

تمام گزارش‌ها با یک ساختار واحد قابل تولید هستند.

---

## اصول اساسی

### اصل ۱: ثبت دوطرفه (Double-Entry)

هر تراکنش مالی باید دو طرف داشته باشد:
- یک طرف بدهکار می‌شود
- طرف دیگر بستانکار می‌شود
- مجموع بدهکار = مجموع بستانکار

**مثال فروش نقدی:**

| حساب | بدهکار | بستانکار |
|------|--------|----------|
| صندوق | ۱,۰۰۰,۰۰۰ | - |
| درآمد فروش | - | ۱,۰۰۰,۰۰۰ |
| **جمع** | **۱,۰۰۰,۰۰۰** | **۱,۰۰۰,۰۰۰** |

### اصل ۲: سند مالی

هر عملیات مالی یک **سند (Document)** تولید می‌کند که شامل یک یا چند **آیتم (DocumentItem)** است.

### اصل ۳: سال مالی

تمام اسناد در یک **سال مالی (FiscalYear)** ثبت می‌شوند. سال مالی بسته قابل تغییر نیست.

### اصل ۴: ماهیت حساب

هر حساب یک ماهیت دارد:
- **بدهکار (Debit):** دارایی‌ها و هزینه‌ها
- **بستانکار (Credit):** بدهی‌ها، سرمایه و درآمدها

## محدوده پکیج

### این پکیج چیست؟

| ویژگی | توضیح |
|-------|-------|
| ✅ سیستم حسابداری دوطرفه | ثبت بدهکار و بستانکار |
| ✅ مدیریت حساب‌ها | درخت حسابداری ۴ سطحی |
| ✅ مدیریت اسناد | ثبت، تأیید، قطعی، ابطال |
| ✅ سال مالی | باز، بسته، افتتاحیه، اختتامیه |
| ✅ مراکز هزینه | تفکیک هزینه‌ها بر اساس پروژه/بخش |
| ✅ چند شعبه | گزارش‌گیری جداگانه هر شعبه |
| ✅ گزارش‌های استاندارد | تراز، دفتر کل، سود و زیان |
| ✅ Audit Trail | ثبت تمام تغییرات |

### این پکیج چه چیزی نیست؟

| ویژگی | توضیح |
|-------|-------|
| ❌ سیستم فروش | فاکتور، سفارش، سبد خرید |
| ❌ سیستم انبار | موجودی، رسید، حواله |
| ❌ سیستم حقوق | فیش حقوقی، کارکرد |
| ❌ سیستم چک | دریافتنی، پرداختنی |
| ❌ سیستم بودجه | برنامه‌ریزی مالی |
| ❌ UI آماده | فقط Backend |

💡 **نکته:** پکیج فقط هسته حسابداری است. سیستم‌های دیگر (فروش، انبار، ...) باید در پروژه پیاده‌سازی شوند و از این پکیج برای ثبت اسناد مالی استفاده کنند.

## موارد استفاده

### فروشگاه آنلاین

| عملیات | ثبت در حسابداری |
|--------|-----------------|
| فروش به مشتری | بدهکار: مشتری / بستانکار: درآمد فروش |
| پرداخت مشتری | بدهکار: بانک / بستانکار: مشتری |
| خرید از تأمین‌کننده | بدهکار: موجودی کالا / بستانکار: تأمین‌کننده |
| پرداخت به تأمین‌کننده | بدهکار: تأمین‌کننده / بستانکار: بانک |

### آموزشگاه

| عملیات | ثبت در حسابداری |
|--------|-----------------|
| ثبت‌نام دانشجو | بدهکار: دانشجو / بستانکار: درآمد شهریه |
| پرداخت شهریه | بدهکار: صندوق / بستانکار: دانشجو |
| پرداخت حقوق مدرس | بدهکار: هزینه حقوق / بستانکار: بانک |

### شرکت خدماتی

| عملیات | ثبت در حسابداری |
|--------|-----------------|
| صدور صورتحساب | بدهکار: مشتری / بستانکار: درآمد خدمات |
| دریافت وجه | بدهکار: بانک / بستانکار: مشتری |
| پرداخت اجاره | بدهکار: هزینه اجاره / بستانکار: بانک |

## نتیجه‌گیری

این پکیج یک هسته حسابداری تمیز، پایدار و قابل استفاده مجدد ارائه می‌دهد که:

- مستقل از Domain پروژه است
- اصول حسابداری را رعایت می‌کند
- API ساده و ثابت دارد
- گزارش‌های استاندارد ارائه می‌دهد
- قابل توسعه و سفارشی‌سازی است
