# معرفی کلی

این پکیج یک **هسته حسابداری دوبل** برای لاراول است. مسئولیت آن نگهداری دفتر حسابداری، کنترل ثبت‌ها و تولید گزارش‌های حسابداری از روی همان دفتر است.

## دامنه واقعی پکیج

این پکیج این قابلیت‌ها را داخل خود پیاده‌سازی می‌کند:

- تعریف حساب‌ها در ساختار درختی
- ثبت سند و ردیف‌های سند
- کنترل قابل‌ثبت بودن حساب‌ها
- کنترل سال مالی فعال و بسته
- شماره‌گذاری سند و `idempotency_key`
- افتتاحیه
- بستن سود و زیان
- برگشت عملیاتی سند
- گزارش‌گیری از دفتر ثبت‌شده

این پکیج این مفاهیم را به‌صورت مستقل پیاده‌سازی **نمی‌کند**:

- مشتری، فروشنده، کالا، خدمت، مالیات، انبار
- ماژول مستقل صندوق و بانک
- گردش‌کار تایید سفارشی
- دوره مالی ماهانه
- اصلاح سال بسته یا برگشت بین‌سال‌ها

## فلسفه طراحی

### ۱. دفتر ثبت‌شده، منبع حقیقت است

گزارش‌ها و مانده‌های دوره‌ای از `document_items` و `documents` ساخته می‌شوند. `cached_balance` فقط برای برخی خواندن‌های عملیاتی و کش lifetime حساب به‌کار می‌رود و منبع اصلی گزارش نیست.

### ۲. ثبت فقط روی حساب تفصیلی

پکیج اجازه نمی‌دهد روی هر حسابی ثبت انجام شود. فقط حسابی که:

- فعال باشد
- `allow_direct_posting = true` داشته باشد
- در سطح `posting_level` باشد
- فرزند نداشته باشد

می‌تواند ردیف سند بگیرد.

### ۳. سال مالی فقط یک وضعیت فعال دارد

چرخه سال مالی در این نسخه `draft → active → closed` است. در هر زمان فقط یک سال مالی می‌تواند `active` باشد.

### ۴. پکیج از دامنه تجاری پروژه جداست

پکیج از طریق `source_type` / `source_id` و Trait `HasAccount` به موجودیت‌های پروژه مصرف‌کننده متصل می‌شود، اما خود آن موجودیت‌ها را مدل نمی‌کند.

## نقاط ورود اصلی

- `Accounting::document()` برای ساخت سند
- `Accounting::account()` برای حساب‌ها
- `Accounting::balance()` برای مانده و گردش
- `Accounting::report()` برای گزارش‌ها
- `Accounting::fiscalYear()` برای سال مالی
- `Accounting::posting()` برای مجوز ثبت
- `Accounting::opening()` برای افتتاحیه
- `Accounting::closing()` برای بستن سود و زیان
- `Accounting::reversal()` برای برگشت عملیاتی

## قراردادهای اصلی سیستم

### سند متعادل

هر سند باید متعادل باشد؛ یعنی جمع `amount * sign` همه ردیف‌ها باید نزدیک صفر باشد. در غیر این صورت `UnbalancedDocumentException` پرتاب می‌شود.

### وضعیت سند

وضعیت‌های موجود:

- `draft`
- `pending`
- `approved`
- `posted`
- `voided`

ثبت قطعی فقط از `draft` و `approved` مجاز است.

### تفاوت `void` و `reversal`

- `void` سند ثبت‌شده را از دفتر posted خارج می‌کند.
- `reversal` سند اصلی را نگه می‌دارد و یک سند جدید با اثر معکوس می‌سازد.

این دو رفتار معادل نیستند و اثر گزارش‌گیری متفاوتی دارند.

## مفاهیمی که فقط به‌صورت فیلد وجود دارند

### Branch

در این پکیج شعبه فقط با `branch_id` روی حساب و سند ذخیره می‌شود. جدول `branches` را خود پکیج نمی‌سازد.

### Cost Center

مرکز هزینه فقط روی `DocumentItem` ذخیره می‌شود. در نسخه فعلی، گزارش‌های هسته‌ای فیلتر مستقل بر اساس مرکز هزینه ندارند.

### Reference

`reference` یک شناسه متنی اختیاری روی سند است. در کد برای آن یکتایی یا رفتار محاسباتی تعریف نشده است.

## سناریوی کلی استفاده

روال معمول استفاده از پکیج چنین است:

1. ایجاد و فعال‌سازی سال مالی
2. تعریف Chart of Accounts
3. ایجاد سند با `DocumentBuilder` یا `DocumentService`
4. افزودن ردیف‌های بدهکار و بستانکار
5. ثبت قطعی سند
6. استفاده از گزارش‌ها یا مانده‌ها برای خواندن اثر سند

جزئیات هر مرحله در فایل‌های بعدی آمده است:

- [02-concepts.md](02-concepts.md)
- [03-architecture.md](03-architecture.md)
- [usage.md](usage.md)

تمام اسناد در یک **سال مالی (FiscalYear)** ثبت می‌شوند. سال مالی بسته قابل تغییر نیست.

### اصل ۴: ماهیت حساب

هر حساب یک ماهیت دارد:
- **بدهکار (Debit):** دارایی‌ها و هزینه‌ها
- **بستانکار (Credit):** بدهی‌ها، سرمایه و درآمدها

### این پکیج چیست؟

| ویژگی | توضیح |
|-------|-------|
| ✅ سیستم حسابداری دوطرفه | ثبت بدهکار و بستانکار |
| ✅ مدیریت حساب‌ها | درخت حسابداری ۴ سطحی |
| ✅ مدیریت اسناد | ثبت، تأیید، قطعی، ابطال |
| ✅ سال مالی | باز، بسته، افتتاحیه، اختتامیه |
| ✅ مراکز هزینه | تفکیک هزینه‌ها بر اساس پروژه/بخش |
| ✅ چند شعبه | گزارش‌گیری جداگانه هر شعبه |
| ✅ گزارش‌های استاندارد | تراز، دفتر کل، سود و زیان |
| ✅ Audit Trail | ثبت تمام تغییرات |

### این پکیج چه چیزی نیست؟

| ویژگی | توضیح |
|-------|-------|
| ❌ سیستم فروش | فاکتور، سفارش، سبد خرید |
| ❌ سیستم انبار | موجودی، رسید، حواله |
| ❌ سیستم حقوق | فیش حقوقی، کارکرد |
| ❌ سیستم چک | دریافتنی، پرداختنی |
| ❌ سیستم بودجه | برنامه‌ریزی مالی |
| ❌ UI آماده | فقط Backend |

💡 **نکته:** پکیج فقط هسته حسابداری است. سیستم‌های دیگر (فروش، انبار، ...) باید در پروژه پیاده‌سازی شوند و از این پکیج برای ثبت اسناد مالی استفاده کنند.
